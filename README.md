# Forecasted-Yield-Calculator
PIS 2026

**Разработка программного модуля для расчёта потенциальной и достижимой урожайности сельскохозяйственных культур.**  
Проект предусматривает реализацию нескольких методик расчёта, работу со справочными таблицами, сохранение истории и возможность использования метеорологических данных.

---

## Этап 1. Разобраться в задаче, понять ожидаемый результат и определить первые шаги работы

### 1. Вопросы, прояснённые на старте

| № | Вопрос | Ответ / Решение |
|---|--------|----------------|
| 1 | **Какие сельскохозяйственные культуры должны поддерживаться в первую очередь?** | В рамках проекта используются данные **YieldSAT**, который включает 4 культуры: **пшеница, кукуруза, соя, рапс**. На этапе MVP фокусируемся на **пшенице и кукурузе** как наиболее типичных зерновых для европейской части России. В перспективе поддерживаются все 4 культуры. |
| 2 | **Какие методики расчёта урожайности мы реализуем?** | **Основной подход** – машинное обучение на мультимодальных данных YieldSAT (спутниковые снимки Sentinel-2, погода, почва, топография) с использованием **глубоких нейросетей** (LSTM, Transformer, ConvLSTM) для попиксельного прогнозирования урожайности. <br> **Дополнительные методики** (для сравнения и валидации): <br> - классическая структура урожая (число стеблей, колосков, масса зерна); <br> - влагообеспеченность (осадки и коэффициент водопотребления); <br> - почвенное плодородие (баллы почвы, поправки). |
| 3 | **Где брать справочные данные и эталонные значения?** | Для ML-подхода – непосредственно из датасета YieldSAT (предварительно обработанные Xarray-файлы). Для традиционных методик – из агрономических справочников и ГОСТов, а также из собранных полевых данных (если доступны). |
| 4 | **Нужна ли интеграция с внешними метеосервисами?** | В рамках YieldSAT все метеоданные уже встроены в датасет. Для дополнительных методик можно реализовать ручной ввод или импорт из CSV/Excel, но внешний API пока не требуется. |
| 5 | **Какой формат результата ожидается?** | - Числовое значение средней урожайности по полю (ц/га или т/га). <br> - Тепловая карта урожайности на уровне пикселей 10×10 м. <br> - При наличии истории – график сравнения с предыдущими годами. <br> На MVP достаточно вывода числа и тепловой карты. |
| 6 | **Тип приложения и технологический стек?** | Десктопное приложение на **Python** с использованием **PyQt5** для графического интерфейса. Для работы с геоданными – `rasterio`, `geopandas`, `xarray`. Для ML – `PyTorch` (или `TensorFlow`). На этапе MVP можно ограничиться консольным интерфейсом с визуализацией через `matplotlib` и `folium`. |
| 7 | **Хранение данных и история расчётов?** | Локальное хранение в **SQLite** (рекомендуется) или в JSON-файлах. Для каждого расчёта сохраняются: координаты поля, культура, год, использованная методика, входные параметры (или ссылки на снимки), полученная урожайность и дата расчёта. |
| 8 | **Критерии приёмки и оценки качества?** | Для ML-модели – метрики регрессии: **MAE, RMSE, R²** на тестовой выборке YieldSAT. Для традиционных методик – сравнение с контрольными примерами из литературы. В финале требуется продемонстрировать работу на реальных полях (из датасета) с ошибкой не более 15% от фактической. |

### 2. Основной пользовательский сценарий

**Актёр:** агроном, аналитик, исследователь.

**Предусловие:** приложение запущено, данные YieldSAT загружены локально или доступны по сети.

**Последовательность действий:**

1. Пользователь открывает приложение и видит главное окно.
2. Выбирает из списка **культуру** (пшеница, кукуруза, соя, рапс).
3. Указывает **местоположение поля** – либо вводом координат (широта/долгота), либо загрузкой геофайла (GeoJSON, Shapefile), либо выбором из предустановленного списка полей YieldSAT.
4. Выбирает **год** (доступны 2016–2024).
5. Нажимает кнопку «Рассчитать».
6. Приложение автоматически загружает соответствующие спутниковые снимки и вспомогательные данные (из кэша или из файлов) и передаёт их в обученную модель.
7. Модель выполняет прогноз и выдаёт:
   - **среднюю урожайность** по полю (в ц/га);
   - **интерактивную карту** (тепловая карта) с распределением урожайности по пикселям.
8. Пользователь может:
   - сохранить результат в историю (кнопка «Сохранить»);
   - посмотреть детали (использованные снимки, метеоданные);
   - запустить расчёт для другой культуры или года.
9. В любой момент пользователь может перейти в раздел **«История»**, где хранятся все сохранённые расчёты с возможностью просмотра, удаления и экспорта.

**Альтернативные сценарии:**
- Если данные для выбранных координат отсутствуют – программа уведомляет об этом и предлагает изменить координаты.
- Если модель не загружена или обучение не завершено – выводится сообщение об ошибке.
- При отсутствии интернета – используются локально кэшированные данные (если они есть).

### 3. Минимально рабочая версия (MVP)

Чтобы получить работающий прототип в кратчайшие сроки, мы ограничиваем функциональность:

| Компонент | Что входит в MVP |
|-----------|------------------|
| **Культуры** | **Пшеница** (как основная) и **кукуруза** (как вторая). Остальные – в будущем. |
| **Регион** | Ограничиваемся одним регионом из YieldSAT – например, **Германия** (наиболее полные данные). |
| **Методика (основная)** | Используем **предобученную модель** (если авторы YieldSAT выложили веса) или обучаем простую модель (например, LSTM или линейную регрессию) на данных за 2016–2022 годы. Традиционные методики пока не реализуем (добавим на этапе 3–4). |
| **Входные данные** | Загрузка данных YieldSAT в формате Xarray (Preprocessed version) для выбранного поля. Можно использовать встроенные индексы полей. |
| **Интерфейс** | Консольный скрипт с аргументами командной строки (пока без полноценного GUI). Визуализация – через `matplotlib` (тепловая карта) и вывод числа в терминал. |
| **Сохранение истории** | Простой JSON-файл, в который записываются: дата, культура, координаты, год, модель, полученная урожайность. |
| **Проверка корректности** | Базовая проверка наличия данных, корректности координат, загрузки модели. |
| **Контрольные примеры** | Используем тестовые поля из YieldSAT, для которых известна реальная урожайность (из датасета). Сравниваем предсказание с фактом. |

**Что НЕ входит в MVP:**
- Полноценный графический интерфейс (будет позже).
- Поддержка всех 4 культур и 4 стран.
- Реализация традиционных агрономических методик.
- Экспорт в PDF/Excel.
- Интеграция с внешними API.
- Детальная обработка ошибок (ограничимся базовыми).

### 4. Первые шаги команды (план на первую неделю)

1. **Изучить YieldSAT** – скачать датасет (Preprocessed version) и разобраться с его структурой, прочитать статью на [сайте проекта](https://yieldsat.github.io/).
2. **Настроить окружение** – установить Python 3.10+, PyTorch, Xarray, Dask, rasterio, geopandas, matplotlib.
3. **Воспроизвести базовый пайплайн** – написать скрипт для загрузки одного поля и визуализации снимков.
4. **Обучить или загрузить модель** – если доступны предобученные веса, интегрировать их; иначе обучить простую модель (например, линейную регрессию или LSTM) на данных за несколько лет.
5. **Создать репозиторий** и залить первоначальную структуру проекта (папки `data/`, `models/`, `utils/`, `scripts/`).
6. **Реализовать консольный интерфейс** – скрипт `predict.py`, который принимает аргументы (культура, год, координаты) и выводит предсказание.
7. **Добавить визуализацию** – отображение тепловой карты с помощью `matplotlib` или `folium`.
8. **Протестировать на контрольных примерах** – сравнить с эталонными значениями из статьи YieldSAT.
